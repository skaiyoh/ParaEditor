# D6 resume: fixes from the independent review

An independent reviewer read D6 and confirmed these by running them in headless Chrome with the real models (`plan/reviews/D6-review.md`; read its findings first).
Make exactly these changes, keeping everything D6 built:

1. `src/render/renderer.ts` around line 443 (through `simplify` at 410 to 421): the back-layer source is simplified with the objects' label texture and the subject clarity table, so the plate inside an object's old silhouette is filtered as if it were the subject (10.9 levels off against a plate filtered as background, and about 5x the texture-edge ink, 1,332 px against 258, exactly where the loop reveals the plate). Simplify the back source with a 1 x 1 zero label texture and an all-zero clarity table; keep the second cache's key as it is. Extend `render.loop-objects` so it would catch this: with `simplify` at its default and the disc fixture, the exposed plate region at a quarter loop must match a plate filtered as background within 2 levels (compute the reference by exporting the still after `reset()` with the same look; the fixture's plate is flat so the reference is that flat color after quantization).
2. `src/render/shaders/geometry.ts` line 15 and the geometry framebuffer: the back mesh writes z = 0 with depth testing off, so where displacement folds the mesh the overlap resolves by index order, not by depth (the reviewer measured a near edge cut by 39 px one way and 9 px the other). Attach a `DEPTH_COMPONENT16` renderbuffer to the G-buffer, write `gl_Position.z = 1.0 - 2.0 * disparity` (nearer wins), enable the depth test with `LESS` inside the geometry draws, clear depth each frame, and keep the object draws' far-to-near order and alpha test. Extend `render.loop` with the reviewer's check: inject a step depth (left half 0.2, right half 0.8) through `injectDepth`, orbit 1, and assert the near edge's cut width at a quarter loop is within 4 px of the width at three quarters (symmetric), instead of 39 against 9.
3. `src/session/scene.ts` lines 179 to 193 (`tap`) and `src/ui/app.tsx` line 16: a tap while the loop runs is not mapped through `LOOP_ZOOM`, so it misses by up to about 57 px at the default orbit. In `session.tap`, while the loop is running, map the point through the inverse zoom about the center before `labelAt` or the decode; the displacement itself is not undone (state that in a comment: at most 2% of the frame). Add a node test for the mapping (center maps to center, a corner maps outward by the zoom).
4. `src/session/scene.ts` lines 106, 167, 294: the loop is gated on the status string, so a Motion toggle during an import restarts the loop on the old photo and the published `Ready` hides earlier errors. Gate the loop on the scene generation and the readiness flags (a scene exists, its generation is current, `plateNeeded(doc)` is false), never on the status text; and do not let `setMotion` republish `Ready` over an error.
5. `src/session/scene.ts` line 296: every slider input while Motion is on calls `requestPlateIfNeeded`, which silently retries a failed inpaint on every drag. Call it only from the Motion toggle and from object add, remove and refine; a failed inpaint shows its sentence and waits for the next explicit Motion toggle.
